# 2026-06-16

## Multiple Routes per Driver — Conflict modal redesigned (Modal 4)

The "Review & Assign" drag-and-drop modal was rebuilt to match the Figma redesign (node `4144:93363`). Visual changes from the initial pass:

- **Order cards**: `#282828` bg, solid teal `D` badge (20×20, `#25B8A7`, dark `#171717` glyph — no longer translucent). Second row shows Droplet icon + product count on the left, planned gal on the right.
- **Route zones**: `#111` outer box, `#1f1f1f` header bar with a **6px pastel accent rail** absolutely positioned on the left — purple `#d8b4fe` for Route 1, blue `#93c5fd` for Route 2. Mirrors the route card accent style used elsewhere.
- **Section labels**: "Orders to be Assigned" / "Routes" — now 16px Light (300 weight), `#a3a3a3`. Previously uppercase caps.
- **Driver row**: driver name + dot + "N/M Assigned" count. Avatar circle with initials removed.
- **No progress bar, no header/footer divider lines** — cleaner, matches current modal conventions.
- **Footer**: "Confirm & Proceed" (bg `#e5e5e5`, dark text) disabled at `opacity 0.5` until all orders are placed; "Cancel" is a bordered ghost button.

## Feature flag — driver multi-route conflict

A **Settings toggle** ("Driver Multi-Route Conflict") was added to gate the entire banner + modal behind a switch. This is a prototype demo affordance — flip it on, the amber banner appears below the top nav; flip it off, everything hides and the app sits normally. State persists to `localStorage`.

Behind the scenes: `SettingsProvider` was moved from `page.tsx` up to `app/layout.tsx` so the page can react to the flag live without a reload.
