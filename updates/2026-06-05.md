## New skill — `/customer-call-analyzer`

Built a **separate analysis skill** for whole-customer understanding, sibling to the frozen route-builder-12 `/single-call-analyzer`:

- New methodology file `CUSTOMER_UNDERSTANDING_METHODOLOGY.md` + command `.claude/commands/customer-call-analyzer.md`; registered in the commands README.
- **Keeps the rigor** (quote-anchoring, verification pass, contradiction pass, weak-signal flagging, forced directional ratings) but **broadens the lens** from "RB v4 adoption fit" to current-state, whole-customer understanding: stakeholder/sentiment map, jobs-to-be-done, **account-health/onboarding issues as first-class**, and **cross-call stitching tags** so a customer's calls compound over time.
- Why separate, not a tweak: the route-builder-12 analyzer is timeframe-locked for apple-to-apple comparison — bending it would break that. Two clean instruments.

## First Fleet Fuels customer analysis

Ran `/customer-call-analyzer` on the demo call → `analyses/fleet-fuels/2026-06-02_fleet-fuels_customer-analysis.md` (verified, quote-anchored).

- **Relationship read:** NEUTRAL–MIXED but high-intent (Fleet Fuels is a **prospect in active onboarding**, not yet live).
- **Headline insight (model correction):** FleetPanda assumed drivers "come back full for the next day"; Fleet Fuels' actual goal is the **inverse** — end dry mid-day → reload at terminal → continue → return empty. This mismatch is likely why the demo "fell a little short." Reload automation is their #1 unmet need.
- The new account-health section caught a real **regression** (tank-monitor levels / planned-gallons no longer appearing on auto-generated orders) that the RB-only analyzer would have dropped as out-of-scope.
- Added plain-English captions to the anchors / frictions / feature-requests tables so the PM can read them at a glance.
